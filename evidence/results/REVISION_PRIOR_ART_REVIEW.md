# Interrupted recovery: refreshed mechanism and prior-art chart

Reviewed 12–13 October 2026. This is a focused technical screen of the implemented successor mechanism, not an exhaustive patent search, infringement opinion, or determination of Indian patent eligibility. The earlier 53/100 assessment is carried forward without a fresh numerical reassessment; 73/100 remains conditional.

## Implemented claim hypothesis

A trusted local controller independently checks a new complete repair continuation from authoritative partial state; authenticates retained staged rows; drains and revokes old worker grants; and atomically publishes a fresh successor identity together with complete resource ownership. Offline partial allocations remain charged until physical reclaim. Immutable witnesses, source validation and promotion checks remain exact. The implementation supports both conventional cached and selective validation. See [contract](../../spec/plan_revision.md).

This combination is the subject to compare. Merely naming a continuation, retaining completed work, using erasure coding, assigning a request identifier, or recording an acknowledgement is not established as a new contribution.

## Candidate elements and evidence status

| Element | Implementation/evidence | Distinction status |
|---|---|---|
| Partial-state assignment retains acknowledged healthy rows and can discard blocking staging | `conventional_partial_plan`; independent finite BFS and blocking-placement regression | Implemented conventional capability; no novel scheduler asserted |
| New exact witness with authenticated STAGED adoption | `PlanRevision.revise`; corrupted-staging rejection; physical row/padding checks | Exact combination is a claim hypothesis, not a demonstrated distinction |
| Drain/revoke old grants before resource transfer | Existing worker revocation barrier reused during revision; paused-worker and late-receipt regressions | Safe protocol ordering implemented; ordinary fencing/revocation foundations require wider prior-art mapping |
| Fresh successor identity, persistent lineage, exact-payload retry | Authority transaction and `plan_revisions`; concurrent duplicate and repeated-revision regressions | Common transactional identity techniques; no independent inventive contribution asserted |
| Failed storage stays charged until physical acknowledgement | `abandon` → RETIRED, no pool write; 1024-byte failed extent retained in every compared run | Necessary correctness property, not proof of a new effect |
| Less repeated work specifically due to selective validation | [Registered comparison](../../experiments/revision_protocol.md), [raw results](revision-advantage-milestone-11.json) | **Not observed: all 12 pairs equal** in witness/actions, retained staging, committed stage bytes and failed charges |

The engineering inference is that this implemented work-retention mechanism does not supply the missing comparative contribution in the tested fixtures: a strengthened conventional controller does the same work. That is separate from a legal finding that any exact claim is anticipated or obvious. No score increase follows.

Do not advance this hypothesis into a large confirmation campaign solely because it works. The next research gate requires a specific remaining mechanism with an explained advantage against a competent conventional baseline, followed by an exact prior-art/combination chart. Final novelty, inventive step, jurisdictional eligibility, inventorship, disclosure history and priority remain unresolved; none can be implemented or inferred from code tests.
