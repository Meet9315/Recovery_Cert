# E20: actual QEMU ZNS command and byte-route gate

16 October 2026. Linux inventory finds WSL kernel 6.18.33.1 with zoned block support but no null_blk module, KVM or preinstalled QEMU. QEMU package 6.2+dfsg-2ubuntu6.31 is installed. Command smoke attempt r1 fails because distribution TCG has no qtest `clock_step`; r2 uses isolated halt-only firmware and passes 15 NVMe completions. Both reports and the exact r2 harness source commit are retained. No performance number is inferred from qtest.

The next declared gate, before byte-route outcomes, uses eight fresh emulator instances: both coding profiles × tight/spare × joint/restricted-separated. Use one new namespace/image per model zone, real capacity exactly one or two 4096-byte code rows, and 1 MiB addressable zone size. The host enforces the model's aggregate open/active budget; namespace-local hardware limits are not claimed to equal a controller-wide limit. Each instance has a fresh random controller serial and no existing image/device input.

Bootstrap exact encoded code rows/retired bytes into the namespaces and bind each zone name to namespace ID, expected capacity and controller identity. Read authoritative reports after every action and verify all LIVE rows/content after every prefix. Materialize each stage with actual NVMe write, authenticate a promoted row, and issue actual open/close/finish/reset commands for their mapped model actions. Code reconstruction must read native emulator bytes; the expected plaintext is a test oracle, never a fallback used to materialize repairs. Count actual new stage bytes separately from bootstrap writes. Preserve parity and losses; both arms receive the same optimized codec.

Pass requires all eight routes complete to the replayed protected target, exact bytes at every prefix, correct report geometry/state/position and no disagreement in expected versus submitted stage work. Stop and retain any failed attempt. Harness corrections use fresh attempt roots/reports, never overwrite an earlier outcome. Record exact kernel/QEMU binary/version, source/harness hashes, namespace bindings, complete model witnesses and NVMe completion statuses.

This gate integrates the model's byte path with actual emulated NVMe ZNS commands. It does not integrate the persistent SQLite authority, implement native power-loss recovery or establish physical failure-domain independence. QEMU restart may discard volatile namespace write pointers even if backing bytes survive; do not infer durable identity/incarnation from a serial alone. Persistent authority/device reconciliation, delayed command drain/takeover, partial/uncertain device fault handling and external/power-cut reproduction remain separately required. These cannot be passed by the nominal byte routes.

Run this validation before timed codec/controller experiments or after they finish; never overlap controlled local timing campaigns. Use [native acceptance contract](../spec/native_zoned_validation.md) for the subsequent durable adapter gate.
