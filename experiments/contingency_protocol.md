# Milestone 13: bounded one-additional-failure gate

Registered 13 October 2026 before evidence collection. This is a feasibility, coverage and mechanism-comparison gate, not a CPU/latency, production fault-tolerance or patentability confirmation.

Freeze the model, independent checker/reference, tests, runner and protocol before collection. Record Git revision, all source/test hashes, protocol and runner hashes. Preserve the earlier failed hypotheses and scores.

Matrix: one 4+2 stripe; 4 or 5 authenticated LIVE rows; 0/1/2 slots in X and independently 0/1/2 in Y; spare slots initially FREE or RETIRED; fault set either source D0 alone or every online scoped domain. This is 72 distinct configurations, including insufficient redundancy/capacity and co-located spares. The additional fault may occur at any committed action boundary before root completion, including boundary zero; no subsequent fault is supported. Complete scope ownership and eventual service by healthy storage are assumptions of the finite model.

Run the robust nominal search with 5000 nominal states, 20000 states per minimum-work branch and 50000 branch checks. Independently search the nominal game with 5000 states and exhaustive assignment feasibility with 10000 candidate permutations per fault. Retain FOUND, INFEASIBLE and UNKNOWN for every case. Independent checker replay must derive complete branch coverage rather than trust a supplied checklist. Save every positive policy, branch keys, witnesses, work and exact terminals. Run separate deliberately exhausted nominal/branch/coverage probes and require UNKNOWN with no policy.

For every positive case, build ordinary conventional cached alternatives on the identical nominal schedule, held resources and fault set. Give that controller the same minimum-work fallback planner and complete snapshot guard. Compare every covered branch's witness, terminal and work. Both controllers may precompute alternatives and must not perform new planning during selection. The independent reference establishes feasibility, not minimum-work proof or production dispatch behavior.

Existing-API smoke collection: four matched pairs (local/workers × source D0 or staged destination X), eight fresh stores. Each uses five LIVE 4+2 rows on D0–D4, FREE X/Y spares, one immutable 1025-byte A object and unrelated foreground content. Inject the declared event at nominal cursor 2, after acknowledged staging and before promotion. Conventional cached uses the ordinary table; selective uses the checked policy bundle. Both use existing source checks, scoped claims, revisions and worker barriers. Check spare-stealing rejection, exact content, whole-store target, no active plans and 1024-byte failed allocation remaining RETIRED. Preserve all events/ledgers/witnesses and zero online replan calls. These smoke cases are not failure-at-every-boundary hardware tests; the finite checker covers every modeled boundary.

No new durable policy-admission API, independent host faults, failures during in-flight I/O, second-fault guarantee or physical fault campaign is included. If ordinary cached alternatives match capability/work, reject this policy representation as a distinguishing contribution. Do not advance to large timing or durable production integration on that basis. Current 53/100 and conditional 73/100 are unchanged unless a separate supported reassessment establishes otherwise.
